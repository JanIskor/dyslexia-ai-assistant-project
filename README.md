# ИИ-ассистент для адаптации учебных материалов обучающимся с дислексией

### AI-powered Educational Platform | LLM · RAG · FastAPI · PostgreSQL · Next.js

Веб-приложение для интеллектуальной адаптации учебных материалов с использованием больших языковых моделей (LLM) и технологии Retrieval-Augmented Generation (RAG).

Система помогает преподавателям преобразовывать сложные учебные тексты в более доступную форму для обучающихся с дислексией, сохраняя исходный смысл, терминологию и образовательную ценность материала.

Проект разработан в рамках выпускной квалификационной работы бакалавра в МГТУ им. Н. Э. Баумана по направлению «Информатика и системы управления», кафедра ИУ5 «Системы обработки информации и управления».

## 1. О проекте

Дислексия может затруднять восприятие письменной информации: длинных предложений, сложных синтаксических конструкций, большого количества терминов и недостаточно структурированных инструкций.

Традиционные инструменты поддержки чтения преимущественно предлагают изменение визуального оформления текста, увеличение интервалов и синтез речи.

Однако изменение оформления не всегда решает проблему сложности самого содержания.

Цель проекта — создать систему, которая помогает преподавателю адаптировать учебный материал на нескольких уровнях:

- **Лексическом:** упрощение сложных формулировок и пояснение терминов.
- **Синтаксическом:** преобразование длинных предложений и сложных конструкций.
- **Структурном:** разделение информации на логические блоки.
- **Визуальном:** выделение ключевых понятий и смысловых элементов.

При этом система должна сохранять факты, терминологию и причинно-следственные связи исходного текста.

### Ключевой принцип

**Human-in-the-loop: итоговое решение о публикации адаптированного материала принимает преподаватель.**

ИИ-ассистент формирует предварительную версию текста, но не передаёт её обучающемуся автоматически.

Преподаватель проверяет результат, сохраняет материал и назначает его конкретному обучающемуся.

## 3. Архитектура системы

Приложение построено на разделении клиентской, серверной и инфраструктурной частей.

### Frontend

Клиентская часть реализует интерфейсы для трёх категорий пользователей:

- Преподаватель.
- Обучающийся.
- Администратор.

Каждой роли доступны соответствующие разделы и операции.

### Backend

Серверная часть отвечает за:

- Аутентификацию и авторизацию.
- Управление пользователями и профилями.
- Работу с учебными материалами.
- Назначение материалов обучающимся.
- Интеграцию с языковой моделью.
- Обработку методических документов.
- Взаимодействие с RAG.
- Управление сообщениями, заявками и уведомлениями.

### Data Layer

**PostgreSQL** используется для хранения:

- Пользователей и профилей.
- Связей преподавателей и обучающихся.
- Учебных материалов.
- Назначений материалов.
- Методических документов и их фрагментов.
- Сообщений и уведомлений.

**MinIO** используется как S3-совместимое объектное хранилище для загруженных файлов.

### AI Layer

ИИ-контур объединяет:

1. Обработку исходного текста.
2. Поиск методических рекомендаций.
3. Формирование контекста для LLM.
4. Генерацию адаптированной версии.
5. Передачу результата преподавателю.

## 4. Retrieval-Augmented Generation (RAG)

Одной из основных особенностей проекта является использование RAG для методически управляемой адаптации текста.

В отличие от классических сценариев RAG, ориентированных на поиск фактов для ответа на вопрос, здесь база знаний используется преимущественно для определения **правил и ограничений преобразования учебного материала**.

### Обработка методических документов

RAG-контур предусматривает следующие этапы:

1. Загрузка методического документа.
2. Извлечение текстового содержимого.
3. Разбиение текста на фрагменты (chunking).
4. Построение векторных представлений (embeddings).
5. Сохранение фрагментов и связанных метаданных.
6. Поиск релевантных рекомендаций при адаптации материала.
7. Передача найденного контекста языковой модели.

### Назначение RAG

Методическая база помогает определять:

- Допустимую глубину упрощения.
- Правила сохранения терминологии.
- Способы структурирования текста.
- Ограничения преобразования для разных жанров.
- Принципы выделения ключевой информации.

Использование RAG позволяет связать генеративную адаптацию с заранее подготовленными методическими материалами.

При этом наличие RAG не гарантирует отсутствие фактических ошибок, поэтому в системе предусмотрена обязательная проверка результата преподавателем.

## 5. Режимы адаптации текста

Система предусматривает три режима преобразования учебных материалов.

### `basic_simplify`

Базовое упрощение текста.

Основные задачи:

- Упрощение сложных формулировок.
- Разделение длинных предложений.
- Снижение синтаксической сложности.
- Сохранение ключевых терминов.
- Сохранение исходного смысла.

### `structured_explanation`

Структурированное объяснение.

Основные задачи:

- Разделение материала на смысловые блоки.
- Формирование последовательного объяснения.
- Выделение отдельных этапов и действий.
- Пояснение причинно-следственных связей.
- Улучшение структуры учебного материала.

### `key_points_focus`

Выделение ключевой информации.

Основные задачи:

- Определение основных мыслей.
- Выделение терминов и определений.
- Акцентирование важных фактов.
- Формирование опорных элементов.
- Облегчение навигации по материалу.

Режимы предназначены для разных сценариев адаптации и могут применяться с учётом особенностей исходного текста.

## 6. Исследовательская часть

В рамках выпускной квалификационной работы проведено экспертно-аналитическое сравнение стратегий адаптации учебного текста.

### Исследуемые стратегии

| Стратегия | Описание |
|---|---|
| S0 | Исходный текст без адаптации |
| S1 | Визуальная разреженность |
| S2 | Лексико-синтаксическое упрощение |
| S3 | Комбинированная адаптация |

Комбинированная стратегия объединяет:

- Упрощение формулировок.
- Разделение информации на смысловые блоки.
- Структурированное объяснение.
- Визуальное выделение ключевых элементов.

### Критерии сравнения

Для оценки стратегий использовались:

1. Лексическая доступность.
2. Синтаксическая простота.
3. Сохранение исходного смысла.
4. Структурность.
5. Визуальная поддержка.
6. Жанровая безопасность.

Каждый критерий оценивался по пятибалльной шкале.

### Результаты исследования

По результатам экспертно-аналитического сравнения комбинированная стратегия была выбрана в качестве основной для проектируемой системы.

Она позволяет объединить лексико-синтаксическое упрощение, структурирование и визуальные опоры.

При этом исследование выявило важное ограничение: повышение доступности текста не должно достигаться за счёт искажения исходного содержания.

Поэтому для системы предусмотрены:

- Контроль сохранения смысла.
- Учёт жанра исходного материала.
- Ограничения на замену терминов.
- Педагогическая проверка результата.

**Важно:** исследование представляет собой сравнение стратегий адаптации по заданным критериям, а не клиническую оценку эффективности системы для обучающихся с дислексией.

## 7. Управление учебными материалами

Приложение поддерживает сценарий подготовки, сохранения и назначения адаптированных материалов.

### Работа преподавателя

Преподаватель может:

1. Ввести текст вручную или загрузить файл.
2. Выбрать режим адаптации.
3. Запустить обработку материала.
4. Просмотреть результат генерации.
5. Проверить адаптированный текст.
6. Сохранить материал.
7. Назначить его обучающемуся.

### Версионирование

В проекте предусмотрено управление версиями адаптированных материалов.

При повторном сохранении материала система учитывает исходный источник и выбранный режим адаптации.

Для назначения обучающемуся используется механизм `snapshot`.

Он фиксирует содержимое адаптированного материала на момент назначения.

Это позволяет отделить уже назначенную обучающемуся версию от последующих изменений материала преподавателем.

### Контроль доступа

Система предусматривает разграничение доступа к данным.

Преподаватель работает со своими материалами и связанными обучающимися.

Обучающийся получает доступ к назначенным ему материалам.

Администратор управляет системными справочниками и методической базой.

## 8. Ролевая модель

### Teacher

Преподаватель:

- Создаёт учебные материалы.

- Запускает построение embeddings.
- Работает с заявками и уведомлениями.

## 12. Основные инженерные решения

### Методически управляемая генерация

RAG используется для поиска рекомендаций по адаптации, а не для произвольного дополнения исходного учебного материала новыми фактами.

### Human-in-the-loop

Генерация отделена от публикации: преподаватель проверяет результат перед назначением.

### Разделение ответственности

Frontend, Backend, Database, Object Storage и AI-контур выполняют отдельные функции.

### Разграничение прав

Доступ к операциям и данным зависит от роли пользователя.

### Фиксация версий

Механизм snapshot позволяет сохранять конкретную версию текста, назначенную обучающемуся.

### Жанровые ограничения

Стратегия адаптации учитывает особенности учебных, научно-популярных, художественных и юридических текстов.
